# Бот программы лояльности

Telegram-бот на [aiogram 3](https://docs.aiogram.dev). Регистрация клиента по номеру
и ФИО, выдача индивидуального ID аккаунта, начисление баллов за оплату и заявки на
списание баллов с подтверждением администратором.

## Что умеет

**Клиент:**
- регистрация: ввод номера телефона → ФИО → выдаётся
  индивидуальный код аккаунта (буквы + цифры, напр. `TTA7K3QF`);
- «Мои баллы» — баланс, ID аккаунта, ФИО, телефон, дата регистрации;
- «История» — последние операции;
- «Списать баллы» — создаёт заявку, она уходит администратору.

**Администратор** (`/admin` или кнопка «🛠 Админ-панель»):
- «Начислить баллы» — вводит телефон **или ID** клиента и сумму оплаты, бот считает
  `сумма × процент` и начисляет баллы, клиенту приходит уведомление;
- «Заявки на списание» — список заявок с кнопками ✅/❌; при подтверждении админ
  вводит сумму покупки, бот списывает баллы (не более `max_redeem_share`% чека)
  и показывает доплату, клиент получает уведомление;
- «Найти клиента» — карточка клиента по телефону или ID;
- «Настройки» — изменить процент начисления, курс балла и минимум для списания
  (сохраняется в базе, перезапуск не нужен).

## Параметры лояльности

Задаются в `.env` как стартовые значения и потом меняются из бота:

| Настройка            | Смысл                                     | По умолчанию |
|----------------------|-------------------------------------------|--------------|
| `accrual_percent`    | сколько % от суммы покупки идёт баллами    | 10           |
| `point_rate`         | сколько ₽ стоит 1 балл                     | 1            |
| `min_redeem`         | минимум баллов для списания                | 1            |
| `max_redeem_share`   | баллами можно закрыть не более N% чека     | 50           |
| `signup_bonus`       | баллов начисляется сразу при регистрации   | 1000         |

Баллы — целые числа, при начислении округляются. При списании админ вводит сумму
покупки, бот сам ограничивает списание долей `max_redeem_share` от чека и показывает
сумму доплаты.

Формат кода аккаунта настраивается в `.env`: `ACCOUNT_CODE_PREFIX` (напр. `TT`)
и `ACCOUNT_CODE_LENGTH` (число случайных символов, по умолчанию 6).

## Шаг 1. Создать бота в Telegram

1. Открой **@BotFather**, `/newbot`.
2. Задай имя и username (должен заканчиваться на `bot`).
3. Скопируй **токен** вида `123456789:AAH...`.
4. Узнай Telegram ID владельца: он пишет боту команду `/myid`. Это число — в `OWNER_ID`.

## Шаг 2. Настроить проект

```bash
cp .env.example .env
```

В `.env` впиши `BOT_TOKEN` и `OWNER_ID`. `ADMIN_IDS` оставь пустым (это опциональные
доп. администраторы-сотрудники).

### Передача бота владельцу

Админ-панель привязана к `OWNER_ID` — это единственный главный админ. Чтобы отдать
бота клиенту: он присылает свой `/myid`, ты ставишь его число в `OWNER_ID`, свой ID
нигде не оставляешь, перезапускаешь бота. Всё — панель только у него.

## Шаг 3. Запуск локально (для проверки)

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python bot.py
```

Открой бота в Telegram, нажми `/start`.

## Шаг 4. Деплой на BotHost

1. Зарегистрируйся на BotHost, создай новый проект → тип **Python (aiogram)**.
2. Загрузи файлы проекта (через веб-панель или git). Не загружай `.venv/` и `*.db`.
3. Укажи:
   - файл запуска: `bot.py`;
   - зависимости: `requirements.txt` (BotHost ставит сам);
   - версия Python: 3.11 или новее.
4. Пропиши переменные окружения в панели BotHost:
   `BOT_TOKEN`, `OWNER_ID`, при желании `DEFAULT_ACCRUAL_PERCENT` и т.д.
   (Либо просто загрузи заполненный `.env` — бот его читает.)
5. Запусти. Бот работает через long-polling, вебхук и открытый порт не нужны.

### Важно про базу данных

Данные лежат в файле `loyalty.db` (SQLite). Убедись, что на BotHost этот файл
попадает в **постоянное хранилище** и не стирается при передеплое. Если такой
гарантии нет — на этапе роста переезжай на PostgreSQL (структура таблиц в `db.py`).

## Ограничения текущей версии

- Телефоны сопоставляются по последним 10 цифрам (подходит для РФ-номеров).
- Один процесс, MemoryStorage для FSM — состояние диалогов сбрасывается при
  перезапуске (на функциональность лояльности не влияет).
- Нет защиты от двойного нажатия кнопок при гонках — для небольшого потока клиентов
  некритично.

## Структура

```
bot.py                — точка входа, запуск polling
config.py             — чтение .env
db.py                 — таблицы и запросы (SQLite)
keyboards.py          — кнопки
handlers/registration.py — /start и регистрация
handlers/client.py       — меню клиента, заявки на списание
handlers/admin.py        — админ-панель
```
